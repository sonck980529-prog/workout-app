# 🏃 홈트 & 러닝 트래커 (Home Workout & Running Tracker)

주 3회, 3분할 홈트레이닝과 러닝 루틴을 기록·추적·모니터링하고, 기록에 따라
점진적 과부하(progressive overload)를 제안하는 모바일 우선(mobile-first)
단일 페이지 웹앱입니다. 기본 3분할 루틴이 초기값으로 들어 있으며, **루틴 탭**에서
분할·운동을 자유롭게 편집하고 데이터를 JSON으로 백업/복원할 수 있습니다.
프레임워크 없이 순수 HTML/CSS/JavaScript(ES modules)로 만들어졌고, 빌드 단계나
설치할 의존성이 없습니다. [wger](https://github.com/wger-project/wger) 에서
영감을 받아, 서버·계정 없이 **혼자 쓰는 온디바이스 버전**으로 만들었습니다.

A mobile-first, single-page web app to log, track, and monitor a 3-way-split
home workout and running routine, and to suggest progression based on your
records. Built with vanilla HTML/CSS/JavaScript (ES modules). No framework,
**no build step, and no dependencies to install.**

---

## 무엇을 하나요? (What it does)

- **오늘 훈련 (Today):** 로테이션에서 다음 순서인 분할을 자동으로 띄우고,
  세트별 무게(kg)와 횟수를 빠르게 입력합니다. 입력하는 즉시 목표 대비 실제
  총 횟수(목표 범위 대비 실제 반복 수, 무게는 별도 지표로 봅니다)와 러닝 페이스
  평가를 보여주고, 운영 원칙에 따른 증량/횟수 증가 제안을 표시합니다. 증량 제안은
  **같은 무게로** 2회 연속 상한에 도달했을 때만 나오며, 두 세션의 무게가 다르면
  증량 대신 횟수 추가를 먼저 제안합니다.
  - **수동 분할 선택:** 기본값은 자동 로테이션 순서이지만, 화면 위쪽의 **분할
    선택** 드롭다운에서 오늘 훈련할 분할을 직접 고를 수 있습니다. 수동으로 골라도
    로테이션 상태는 바뀌지 않으며, 저장 후 다음 순서는 **가장 최근에 저장된
    세션**을 기준으로 자동 진행됩니다.
- **루틴 (Routine):** 분할(스플릿)과 각 분할의 운동을 직접 추가·수정·삭제하고
  로테이션 순서를 바꿀 수 있습니다. 운동은 **이름, 기본 무게, 목표 최소/최대
  횟수, 세트 수, 다리당 여부**를 편집합니다. 기본으로 제공되는 3분할 루틴이
  시드(초기값)로 들어가 있으며, 이를 그대로 쓰거나 자유롭게 바꿀 수 있습니다.
  - **운동 라이브러리:** 자주 쓰는 운동을 라이브러리에 모아두고, 운동을 추가할
    때 라이브러리에서 골라 폼을 빠르게 채울 수 있습니다. 기본 분할의 운동에 더해
    벤치프레스·데드리프트·바벨 로우·덤벨 컬·플랭크 등이 미리 들어 있습니다.
  - **백업/복원 (Backup / Restore):** 서버가 없는 앱이므로 데이터 이동·보관은
    JSON 파일로 합니다. **내보내기** 버튼은 모든 기록·루틴·운동 라이브러리를
    `htracker-backup-YYYY-MM-DD.json` 파일로 저장하고, **가져오기** 는 그 파일을
    읽어 현재 데이터를 **덮어씁니다(replace)**. 다른 기기로 옮기거나 브라우저
    데이터를 지우기 전 백업하는 용도입니다. 형식이 올바르지 않거나 내부적으로
    일관되지 않은(예: 로테이션 순서가 존재하지 않는 분할만 가리키거나 분할이 비어
    있는) 파일은 거부되며, 기존 데이터는 그대로 유지됩니다.
- **러닝 인터벌 입력:** 인터벌은 전체 평균 페이스와 **반복 구간(1km 반복) 페이스**를
  따로 입력합니다. 목표 페이스 구간(5:10~5:20/km)은 반복 구간에만 적용되므로,
  평가와 추이 차트 모두 반복 구간 페이스를 기준으로 판단합니다.
- **기록 (History):** 저장된 모든 세션을 최신순으로 보여주고, 세트별 무게·횟수
  (러닝은 거리·페이스·반복 구간 페이스)와 날짜를 모두 수정하거나 삭제할 수
  있습니다. 저장 시점에 각 운동의 **표시 이름을 세션에 함께 스냅샷**하므로, 이후
  루틴에서 운동 이름을 바꾸거나 삭제해도 지난 기록은 원래 이름 그대로 읽을 수
  있습니다(스냅샷이 없는 예전 기록은 현재 루틴 이름으로 표시됩니다).
- **추이 (Trends):** 운동/지표를 선택하면 기록된 세션의 추이를 **인라인 SVG
  차트**로 보여줍니다. 외부 차트 라이브러리나 CDN을 전혀 사용하지 않습니다.
  - 근력 운동: **세트 최고 중량**(라인 차트), **총 볼륨**(막대 차트)
  - 러닝: **평균 페이스**(라인 차트) — 이지런/인터벌 **목표 페이스 구간**을
    음영 영역으로 함께 표시
  - 최근 값이 직전 대비 상승/유지/하락인지 표시하며, 페이스는 더 빠른(값이
    작은) 쪽을 개선으로 간주합니다.
  - 데이터가 2개 미만이면 차트 대신 `기록이 쌓이면 추이가 표시됩니다`
    안내를 보여줍니다.
  - 화면 맨 위에는 **주간 리뷰 요약** 카드가 표시됩니다(아래 참고).

## 자동 코칭 (Auto-coaching)

기록이 몇 주(약 3세션/3주) 쌓이면, 추이를 반영해 목표를 조정하도록 **제안**하는
코칭 카드가 나타납니다. **모든 조정은 자동으로 반영되지 않습니다.** 카드에서
[적용]/[디로드 적용]을 눌러 내가 수락해야만 루틴 목표가 실제로 바뀌며, 다음
훈련부터 반영됩니다. 분석 로직은 순수 모듈 `js/coaching.js` 에 있고, 서버 없이
앱을 열거나 조작할 때 **브라우저에서 계산**됩니다(백그라운드 작업이 아닙니다).

- **목표 상향 제안 + 원터치 적용:** 근력 운동이 최근 **약 3세션(3주)** 동안 모든
  세트가 목표 상한에 **같은 무게로 연속 도달**하면 `목표 상향 제안` 카드가
  뜹니다. 현재 목표(예: `12kg · 6~10회 × 4세트`)와 제안(예: `14.5kg …
  (+2.5kg)`, 맨몸운동은 반복 목표 `+1~2회`)을 나란히 보여주고 **[적용]** /
  **[나중에]** 버튼을 제공합니다. [적용]을 누르면 `js/storage.js` 의
  `updateExercise` 로 루틴 목표가 실제로 바뀌어 다음 훈련의 세트 입력에 새 목표가
  미리 채워집니다. 상한 연속 도달이 부분 달성이면 `증량 제안까지 2/3` 처럼
  진행도를 보여주고, 아직 한 번도 도달하지 못했으면 카드를 띄우지 않습니다.
- **정체 감지 + 디로드 제안:** 반대로 최근 **약 3세션** 연속 상한에 못 미치는
  정체가 감지되면 `정체 감지` 카드가 떠서 **디로드**를 제안합니다. 가중 운동은
  무게를 **약 10%(≈ ×0.9, 0.5kg 단위 반올림)** 낮추도록, 맨몸/그 외에는 **세트를
  1세트 줄이도록**(세트 −1) 제안하며 **[디로드 적용]** / **[유지]** 버튼을
  제공합니다. 낮출 무게의 기준은 **실제로 정체된 무게(최근 세션에서 일관되게
  들던 무게)** 이며, 이 값을 알 수 없을 때만 루틴 기본 무게로 되돌아갑니다
  (증량 제안이 관측 무게를 기준으로 삼는 것과 동일한 방식입니다). 강제가 아니라
  회복을 위한 제안입니다.
- **주간 리뷰 요약:** **추이** 탭 맨 위에 이번 주 요약 카드를 보여줍니다.
  포함 내용은 **이번 주 운동 횟수**, **PR(개인기록) 갱신**, **지난주 대비 총 볼륨
  변화**(▲/▼ %), **러닝 페이스 변화**(더 빠르면 개선), **다음 주 추천** 입니다.
  **다음 주 추천**은 PR·볼륨·페이스 신호에 기반한 요약 문구를 항상 보여주며,
  진행 중인 증량 제안이 있으면 별도의 **진행 중 제안** 줄에 `풀업 증량 대기 2/3`
  처럼 함께 표시합니다(둘 중 하나가 다른 하나를 가리지 않습니다).
  여기서 "이번 주"는 **가장 최근 세션 날짜를 끝으로 하는 최근 7일(rolling 7 days)**
  을 뜻하며, "지난주"는 그 직전 7일입니다(고정된 달력 주가 아닙니다). 비교할
  지난주 데이터가 없으면 그에 맞는 안내 문구를 보여줍니다.

[나중에] / [유지] 는 아무것도 바꾸지 않고 해당 카드만 접습니다(세션 중에만
기억하는 인메모리 방식이라, 앱을 다시 열면 조건이 유지되는 한 제안이 다시
나타납니다). 즉 **제안 → 내가 수락(적용)** 흐름이며, 자동 반영은 없습니다.

## 3분할 로테이션과 운영 원칙 (3-split rotation & operating rules)

주 3회 기준으로 다음 순서를 반복합니다:

1. **등·가슴** — 12kg 풀업, 12kg 링딥스, 맨몸 풀업, 맨몸 링딥스
2. **어깨·하체·복근** — 40kg 백스쿼트, 40kg OHP(4세트), 40kg 런지(다리당),
   사이드 레터럴 레이즈, 행잉 레그레이즈
3. **러닝** — 이지런(조깅) 5~7km, 6:15~6:40/km · 또는 인터벌 총 7~8km
   (웜업 1.5km + 1km × 4회 + 회복 조깅 + 쿨다운), 반복 구간 5:10~5:20/km
   (목표 페이스 구간은 **반복 구간**에만 적용됩니다. 전체 평균은 웜업·회복·쿨다운
   때문에 자연히 더 느립니다.)

운영 원칙:

- 주 3회 기준으로 등·가슴 → 어깨·하체·복근 → 러닝 순서로 반복합니다.
- 각 세트는 1~2회 여유(RIR 1~2)를 남기고 종료합니다. 기록이 없는 날은 목표를
  강행하지 않습니다.
- 같은 운동을 2회 연속 수행하며 **모든 세트가 상한에 도달**하면, 다음 회차에만
  소폭 증량하거나 1~2회를 추가합니다. 단, 증량은 두 세션이 **같은 무게**였을 때만
  제안하며, 무게가 달랐다면 먼저 횟수를 추가해 기준 무게를 안정시킵니다.
- 러닝은 빠르게 달리는 것보다 이지런의 호흡과 회복을 우선합니다.

## 데이터 저장 방식 (Storage model)

- 모든 기록은 브라우저의 **localStorage**(키: `htracker.v1`)에 저장됩니다.
- 저장 형식에는 **스키마 버전(schemaVersion)** 이 있으며, 기록·루틴·운동
  라이브러리가 하나의 JSON 구조로 함께 보관됩니다. 예전에 세션만 저장돼 있던
  데이터도 앱을 열면 **기존 기록을 그대로 유지한 채** 기본 루틴·라이브러리가
  자동으로 붙으면서 최신 버전으로 마이그레이션됩니다(스키마 버전 상승 시에도
  기존 기록은 보존됩니다).
- **단일 사용자, 온디바이스 전용(on-device only)** 입니다. 서버나 계정, 네트워크
  전송이 전혀 없습니다. 기기와 브라우저를 벗어나 데이터가 나가지 않습니다.
- 브라우저 데이터를 지우면 기록도 함께 삭제됩니다. 이에 대비해 **루틴 탭의
  설정/백업**에서 JSON으로 내보내 두면 다른 기기로 옮기거나 나중에 복원할 수
  있습니다.
- '오늘 훈련'의 다음 분할은 **가장 최근에 저장된 세션의 순서**를 기준으로 정해집니다
  (저장 날짜가 아니라 저장된 순서). 따라서 기록을 과거 날짜로 수정하거나 가장 최근
  세션을 삭제하면 다음 분할이 바뀔 수 있습니다. 단일 사용자·온디바이스 앱에서는
  의도된 단순한 동작입니다.

## 로컬에서 실행하기 (Run locally)

ES modules를 쓰기 때문에 정적 파일 서버로 열어야 합니다(파일을 직접
`file://` 로 열면 모듈이 로드되지 않습니다).

```sh
python3 -m http.server 8000
```

그런 다음 브라우저에서 http://localhost:8000/ 을 엽니다.

## 로직 테스트 실행하기 (Run the logic tests)

순수 로직(진행 규칙, 볼륨/페이스 계산, 차트 스케일 helper)에 대한 의존성 없는
node 테스트가 포함되어 있습니다:

```sh
NODE_OPTIONS= node tests/logic.test.mjs
```

> 참고: 이 샌드박스 환경에서는 `NODE_OPTIONS` 를 비워야(`NODE_OPTIONS= `) node가
> 정상 실행됩니다.

## 빌드/의존성 (Build & dependencies)

**빌드 단계가 없고, 설치할 의존성도 없습니다.** 차트는 순수 vanilla JS로 생성한
인라인 SVG이며 외부 라이브러리/CDN을 사용하지 않습니다.

## 프로젝트 구조 (Project structure)

```
index.html          앱 셸 + 모바일 뷰포트
css/styles.css      모바일 우선 다크 테마 스타일
js/data.js          루틴/운동 시드 데이터 (순수)
js/storage.js       localStorage 저장/조회 + 로테이션 + 루틴·라이브러리 CRUD + 백업/복원
js/progression.js   진행 규칙·볼륨·페이스 계산 (순수)
js/coaching.js      자동 코칭 분석: 목표 상향/정체 감지/주간 리뷰 (순수)
js/charts.js        인라인 SVG 라인/막대 차트 (순수)
js/app.js           UI 와이어링 (오늘/기록/추이/루틴 + 백업 + 코칭 카드)
tests/logic.test.mjs  node 로직 테스트
```
